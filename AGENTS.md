# Agent Instructions

## Bossman First

Before public-site, SEO, content, conversion or route changes, ask Bossman for current site truth, standards, Fleet Guards, evidence, actions, and next safe actions. Run from this repository:

```sh
./scripts/bossman-site-context
```

If the launcher cannot find Bossman, use a verified checkout through `BOSSMAN_SITE_CONTEXT_HELPER` or the global Git key `bossman.siteContextHelper`. Never copy a machine-specific path into this file. A helper-path or instruction repair may proceed without changing public output or Bossman's accepted facts.

Check the returned evidence, standards, Fleet Guards, and repo mapping against this task. If site identity, repo mapping or an accepted fact needed for the proposed change is unresolved, stop that affected change and report the exact gap. Unrelated read-only work and contract repairs can continue. Missing or partial data is not zero.

Reuse a successful context check within unchanged work; refresh when the site, scope or relevant Bossman state changes. Read only the linked instructions needed for the task.

## Delivery and handoff

Carry existing approval through routine fixes and relevant checks without asking again. Merge, deployment, provider writes and page removal still require authority covering those actions; these instructions grant none. Fix material failures and rerun affected checks. Reuse valid same-tree proof instead of repeating unrelated suites.

For an approved cleanup, reuse the accepted evidence and URL manifest. Preserve legal, quote, contact and operational paths. Do not rewrite retained copy, redesign links or add redirects outside the approved treatment.

Before finishing controlled site work, answer Bossman's repo handoff checklist:

- Did this work add, update, or satisfy a Fleet Guard?
- Did this work change public site output?
- If public output changed for SEO, content, conversion, brand, trust, technical health, or agentic visibility, was a Site Improvement Experiment created or attached?
- Was baseline evidence captured or explicitly marked missing?

Complete all authorized delivery steps, including merge, live proof and experiment recording when covered by the instruction. Report implementation, merge, deployment and measured results separately. State exactly what was tested; sampled URLs do not prove the whole estate.
